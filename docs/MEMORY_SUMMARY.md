# 记忆摘要

参考 ChatGPT 公开的高层概览、纠正、减少引用和删除并关闭体验：[Memory in ChatGPT](https://help.openai.com/en/articles/8590148-memory-in-chatgpt)、[Dreaming 说明](https://openai.com/index/chatgpt-memory-dreaming/)。这是本应用在官方 DeepSeek API 上的实现，不声称复现 OpenAI 的后台学习算法。

## 怎么用

打开「设置 → 记忆」，默认显示「摘要」。切到「条目」可搜索和添加记忆，「设置」可调整引用方式、备份和清空记忆。摘要按“关于你、偏好与交流方式、工作项目与计划、其他事项”分组，随已保存条目变化更新；无需等待模型调用。

- **智能整理**：由 DeepSeek 合并和精简相近表述，保留每条原始记忆的对应关系。所有参与条目必须覆盖一次，不能遗漏或引用不存在的 ID。
- **来源与直接编辑**：查看原始条目，直接改写，无额外模型调用。合并表述对应多个来源时逐条编辑原记忆。
- **补充或纠正记忆**：展开同名区域后输入说明。例如“我现在住在北京，不是上海”。先预览原内容、新内容和删除项，点击“保存这些修改”后才更新实际记忆。也可选中摘要中的文字，只让模型处理对应来源。
- **不再提起**：从对应记忆行的「⋯」菜单选择。暂时排除这些保存条目及其已知原消息来源，可恢复引用。原聊天不删除，其他旧聊天里的不同措辞仍可能被检索；这不等同于对所有历史进行语义封锁。需要更广泛排除时关闭历史引用或删除原聊天。
- **删除并关闭记忆**：确认后清空保存条目、摘要缓存和不再提起状态，同时关闭记忆及历史引用。保留原聊天记录。

## 页面排版

参考 Linear Preferences 的公开截图，把控件按用途分组并沿右侧对齐。摘要以正文为主，条目与设置通过页签切换。来源保留在正文下方，编辑与引用操作移到每行的「⋯」菜单。 [Linear Preferences 截图](https://nicelydone.club/examples/screens/ce737dfd-7b07-41ac-9668-7d0277e5425e)

沿用 App 的字体、蓝色与深浅主题。页面标题为 20 px，条目正文为 14 px，来源与日期为 11–12 px。组间间距为 20–24 px。窄屏使用一列内容，主导航与页签保留在阅读区域上方，长中文和英文路径在行内折行。

## 范围与费用

摘要建立在已保存记忆之上。相关旧聊天仍按问题做本机检索，本功能不会自动批量上传旧聊天、附件或全部档案，也没有跨设备云同步或完整的后台 Dreaming 进程。

查看、直接编辑、主题分类、隐藏和恢复均在本机完成。只有主动点击“智能整理”或“预览修改”才额外调用一次 `deepseek-flash`。请求最多约 24000 字符输入资料、4000 输出 token、30 秒超时，不自动重试，费用来自官方 API。

智能整理只改变摘要的表述；后续聊天继续使用原始条目，避免将模型整理时的推测当成新事实。文字纠正则在明确展示预览并保存后，更新实际条目，标为手动记忆，避免自动整理覆盖。

模型请求只发送必要的条目字段，不携带本机摘要缓存。自动提取新记忆时也排除已设为不再提起的条目。

## 一致性与备份

- 摘要与原条目 ID 和内容快照绑定。条目被更正、删除或设为不再提起后，旧摘要失效，立即回到最新原文的本机概览。
- 修改使用 IndexedDB 原子事务和完整快照比对。资料变化后，旧提案不能覆盖新内容；清空、关闭或更换 Key 后的迟到模型响应也不能恢复旧记忆。
- 记忆数据库和聊天数据库版本不变。摘要缓存与不再提起标记附在现有记忆记录上，原对话不迁移。
- JSON 备份格式升级至 v2，保留不再提起标记；导入兼容 v1/v2，继续去重合并。导入时重新建立概览，不信任导入文件里的旧摘要缓存。旧版本客户端不能读取 v2 文件，避免无声丢失排除偏好。
- 智能请求严格校验 JSON、已知来源、重复 ID、修改数量和常见凭据。模型省略空的 `changes`/`forget` 数组时按空数组处理；不推断删除项。

## 验证

`npm test` 覆盖分类、失效规则、模型来源校验、修改校验及排除规则。

`ANDROID_APP_ID=app.ohmydeepseek.android.importtest node scripts/overview-smoke.mjs` 仅允许独立测试包，用人工资料和模型 fixture 检查完整流程、实际请求注入、划选、旧提案防覆盖、备份、重载和清空取消，以及窄屏/深色模式。

`node scripts/live-overview-check.mjs --synthetic-paid-test` 使用已配置 Key 发起两次收费验证，只发送人工记忆，不读取私有聊天或记忆库、不修改主 App 数据，也不输出密钥。实际 API 返回过三条摘要和一条居住地纠正；发现省略空数组的兼容情况后，修复解析并回放同一实际响应通过，未为回放额外调用 API。

真实用户资料、模型原始运行记录和诊断日志留在本机忽略目录，不进入公开仓库。
