# 账户余额：设计与实现

## 目标与参考

按用户指定的 `design-reference-workflow`，只增加与余额有关的界面，保留现有 DeepSeek 蓝色、字体和设置结构。主信息是账户可用余额；明细与提醒设置放到下一层，不占用聊天正文。

## 最小视觉规格

- 方向：安静的账户读数。金额为主、明细为辅；警告就地呈现，不弹反复打断聊天的模态框。
- 入口：侧栏底部卡片；手机顶栏和收起侧栏时使用紧凑金额按钮；API Key 设置旁也有入口。
- 布局：卡片 14 px 内边距；明细弹窗约 440 px，窄屏距边缘 16 px。主金额 30–42 px，摘要 25 px，正文 12–14 px；中文沿用现有系统字体回退，数字用 `tabular-nums`。
- 色彩：沿用品牌蓝，正常状态低饱和绿，偏低与不足使用琥珀色和明确文字；失败以错误文案与“上次结果”区分。深色模式有对应颜色。
- 状态：未配置 Key、首次加载、正常、偏低、不足、刷新中、网络失败、鉴权失败、服务异常、格式异常、隐藏金额。
- 动效：只在刷新时旋转图标；尊重 `prefers-reduced-motion`。数字不做滚动计数动画。

## 数据与行为

使用官方 [`GET /user/balance`](https://api-docs.deepseek.com/api/get-user-balance/)，返回可用状态及各币种的总额、充值额和赠送额。该余额属于账户，不是某一个 Key 的独立限额。只查询余额，不调用收费模型。

- 有 Key 时启动查询；保存新 Key 时取消旧请求、清空旧金额并重新查询，迟到的旧结果不能覆盖新账户。
- 回到前台或联网时按 60 秒缓存更新；API 使用后约 1.8 秒触发去抖刷新，自动请求最短间隔约 5 秒。慢请求期间新增的用量不会丢失刷新，后台不轮询。
- 手动刷新、15 秒超时、请求合并和短时防连点。服务端可能延迟结算，界面显示更新时间，不承诺逐笔实时对账。
- 查询失败不会变成零余额；同一账户的网络/服务错误保留上次结果并明确标旧。鉴权失败直接移除旧金额，提供检查 Key 的入口。
- 默认提醒阈值为 CNY 5、USD 1，可分别调整；这是本应用的提醒设置，不是官方限制。0 表示只提示余额不足。多币种不相加、不换汇；账户不足状态优先。
- 极小正余额显示为“小于 0.01”，避免四舍五入成零。明细金额可通过桌面悬停查看官方原始精度。
- 可隐藏金额；金额不进入 localStorage、聊天备份或仓库，只保留在本次运行内。仅隐藏偏好和阈值在本机保存。
- 官方账户链接交给外部浏览器；应用不代用户充值。

## 验证方式

`npm test` 含余额响应校验、币种处理、状态判断及极小余额格式测试。

`ANDROID_APP_ID=app.ohmydeepseek.android.importtest node scripts/balance-smoke.mjs` 只允许独立测试包，使用人工余额 fixture，禁止收费请求。覆盖初次查询、隐藏金额、阈值、错误保旧、换 Key 并发、用量刷新，以及 Android WebView 中的 320/412 px 响应式和深色模式；视口模拟不等同于物理手机实测。原始截图与记录仅保留在忽略目录 `evidence/local/`。
